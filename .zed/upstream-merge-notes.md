# Слияние с upstream: решения и ловушки

Составлено 2026-11-26 по слиянию с `v1.28.0-pre` (merge `0269bf1b6e`, дополнения
`096e225b7b`, `61ac6e72e6`). Следующее слияние идёт по этому списку.

## Подготовка

- Upstream-тег `v1.28.0-pre` из ветки релиза, не предок `upstream/main`. Базу
  слияния искать через `git merge-base`, а не по главной ветке.
- Локально нет `cargo`: слияние и проверки идут через GitHub Actions. Цикл:
  временная ветка `dev_check` (сборка `cargo check --workspace --all-targets` на
  раннере форка) и `dev_tests` (отдельные тесты), оба workflow лежат только на
  временной ветке. Ветку строить через `git read-tree` и `commit-tree`, чтобы
  каждый пуш был fast-forward. Журналы читать на раннере в
  `/var/lib/ci-handoff-zed/<прогон>/`.
- `workflow_dispatch` работает только для workflow из ветки по умолчанию.

## Решения, которые встретятся снова

| Что | Решение |
|---|---|
| `crates/zed/RELEASE_CHANNEL` | Из тега приходит `preview`: вернуть `dev`. |
| Workflow upstream | Удалить все `.github/workflows/*`, кроме `fork_bundle.yml` и `fork_release_notes.yml`. Свои `.github/actionlint.yml` и `.github/actions/run_tests` оставить. |
| `Cargo.lock` | Локально не пересобрать. Собрать объединение двух файлов (все пакеты upstream плюс пакеты форка), дать cargo пересчитать его в CI и закоммитить тот файл, что получился. |
| Корневой `Cargo.toml` | Версии upstream, добавки форка (патчи в `vendor/`, ruff/ty, pdfium, sqruff, tokio-socks, zip, miette) оставить. `log` и `toml_edit` с суперсетом функций. |
| `icu_segmenter` | `>=2.1.1, <2.4`: движок HTML (servo, mozjs_sys, icu_capi) держит ICU4X 2.1, upstream просит 2.3. |
| `jupyter-websocket-client` | Оставить на `async-tungstenite 0.34.1` в замке, иначе в `repl` два разных `WebSocketStream`. |
| Git Graph | Оставить свой файл (метки, аватары, меню ссылок), портировать из upstream подсказки, сворачиваемые детали, теги, скрытие колонок, меню «+N». Колонку «Автор» не переносить: автор рисуется в узле коммита. |
| Языковые серверы | Модель запуска и остановки upstream, поверх неё покой форка «ничего не стартует, пока не попросили» внутри `can_start_language_server`. Ограничение языками действует только при ручном запуске. |

| nextest | `test_random_columnar_selections` 300 с, `test_random_split_editor` 600 с. |

## Что правилось в тестах upstream под интерфейс форка

- Тест окна настроек берёт окно выше самого высокого последнего элемента.
- Кнопки разрешений агента получили селектор `PERMISSION_ACTIONS-*`: форк
  выравнивает их вправо.
- Тест многокурсорного дополнения регистрирует обработчик раскрытия до
  открытия меню, иначе старый обработчик отвечает не на тот запрос, а таймер
  мигания курсора скрывает зависание.
- Названия инструментов `db_list_connections` и `db_run_query` входят в список
  профиля агента.
- Проверка `xtask` для objc терпит `wgpu-hal` и `wr_glyph_rasterizer` (граф
  Servo на macOS).

## Ловушки

- Раннеры GitHub теряли DNS зеркал Ubuntu на часы: ошибка не в коде, брать
  раннер форка и дать шагу `apt` `timeout-minutes`.
- ВМ раннера общая (15 ГБ): собственные задачи владельца машины убивают `rustc` по памяти
  (`dmesg`, `oom_score_adj:800`, в журнале CI только «process didn't exit»).
  Перед тяжёлым прогоном смотреть `free -m`, чужие процессы не трогать,
  упавшую часть запускать заново `gh run rerun <id> --failed`.
- Том сборки раннера фиксированного размера (около 19 ГБ): каталог `debug`
  от `dev_check` надо удалять после проверок, иначе сборка релиза падает с
  «No space left on device».
- Образ CI меняется под ногами (новый `coreutils` отказался запускать
  `printenv` под чужим именем). Падение, которое одинаково воспроизводится при
  повторе, не случайное: читать журнал.
- Код под `cfg(windows)` и `cfg(macos)` при слиянии вслепую не собирается и не
  запускается. Сборка Windows и macOS по расписанию раз в 30 дней, лишних
  не запускать; правки только для них вливать с `[skip ci]` и ждать плановой
  сборки.
- Тест движка HTML по пикселям на macOS расходится на один пиксель (316 против
  317); причина не найдена, см. бэклог U1.
- Выпуск: описание в `.github/release-changes/<тег>.md` пишется после
  публикации и пушится отдельно, `[skip ci]` в последнем коммите останавливает
  все workflow.
