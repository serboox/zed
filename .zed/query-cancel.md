# Отмена запроса к базе

Запрос, который ушёл на сервер, можно остановить: красный квадрат «Стоп»
останавливает **выражение на сервере**, а не только перестаёт его ждать, и
откатывает открытую транзакцию.

## Что происходит при нажатии

1. Выражение уже помечено комментарием `/* zed-run-<uuid>-<n> */` в начале текста.
2. Провайдер открывает **отдельное** соединение и находит выражение в списке
   того, что сервер выполняет сейчас, по этой метке: `SHOW FULL PROCESSLIST`
   в MySQL, `pg_stat_activity` в PostgreSQL, `system.processes` в ClickHouse.
   По метке, а не по запомненному номеру соединения: номер устаревает после
   переподключения и другой у транзакции, которая живёт на своём соединении.
3. Серверу говорят остановить выражение: `KILL QUERY` / `pg_cancel_backend` /
   `KILL QUERY … SYNC`.
4. Если выражение не остановилось за 5 секунд — серверу говорят закрыть сессию
   (`KILL` / `pg_terminate_backend`); сессия, закрытая так, не повторяет
   выражение на новом соединении.
5. Если и это не помогло за 5 секунд, вызывающий перестаёт ждать.
6. Если соединение держит транзакцию — она откатывается (`ROLLBACK`). Откат идёт
   на том же провайдере, на котором шло выражение, и только если это та же
   транзакция, что была открыта в момент нажатия.
7. Выражения, ждавшие очереди к соединению, не стартуют.
8. Скрипт останавливается на остановленном выражении; остальные не запускаются.

Ответ сервера после нажатия читается честно:

| Ответ | Что показано |
| --- | --- |
| ошибка вида «выражение остановлено» (SQLSTATE 57014, 70100, обрыв сессии) | «Cancelled. The server stopped the statement.» |
| строки: выражение успело закончиться | результат как есть; в отчёте «Not stopped: the statement had already finished.» |
| собственная ошибка выражения (например, упавший COMMIT) | эта ошибка, не «cancelled» |

## Где кнопка

| Место | Когда видно | Как выглядит |
| --- | --- | --- |
| Желоб консоли, строка выполняемого выражения | пока выражение идёт | красный квадрат внутри кольца загрузки; клик останавливает |
| Область результата | пока результат загружается | рамочная красная кнопка «Stop» под индикатором |
| Строка состояния окна | пока идёт хотя бы одно выражение, в любой вкладке | «N queries · 12 s» со списком и красная «Stop» |
| Клавиатура | Escape в консоли, где идёт выражение и нет меню | действие `database_panel::CancelQuery` |
| Клавиатура, везде | Ctrl+Shift+F2 (macOS: Cmd+Shift+F2) | останавливает всё, что идёт |

Escape срабатывает только когда в консоли идёт выражение и не открыт список
подсказок или действий, поэтому не отнимает клавишу ни у чего другого.

## Что умеют разные базы

| База | Остановка на сервере | Откат |
| --- | --- | --- |
| MySQL | `KILL QUERY`, затем `KILL` | да, транзакция в режиме транзакции |
| PostgreSQL | `pg_cancel_backend`, затем `pg_terminate_backend` | да |
| ClickHouse | `KILL QUERY … SYNC` | нет транзакций |
| SQLite, MongoDB, Redis, Cassandra, Aerospike | нет: вызывающий перестаёт ждать, сервер может доделать | SQLite — если держит транзакцию |

Для баз без остановки отчёт говорит прямо: «Stopped waiting. This server cannot
be asked to stop a statement, so it may still be running it.»

## Что не покрыто

- «Выполнить в файл» (`execute_to_file`) имеет свою отмену по флагу при записи
  каждой строки; общая кнопка до него не дотягивается.
- MySQL: DDL и таблицы без транзакций не откатываются сервером; кнопка
  останавливает выражение, но того, что оно уже сделало, не возвращает.
- Остановка между двумя выражениями скрипта прекращает скрипт, но откатывать
  нечего: выражение в этот момент не выполняется.

## Как проверено

- Тесты на настоящих MySQL 8.4, PostgreSQL 16 и ClickHouse 24.8 в контейнерах:
  остановка, сессия жива после остановки, откат транзакции после остановки,
  выражение из очереди не стартует, выражение, остановленное закрытием сессии,
  не выполняется повторно.
- Тесты хранилища на двойнике сервера: порядок шагов, закрытие сессии, отказ
  сервера отвечать, откат только своей транзакции, переподключение во время
  остановки.
- Тесты интерфейса с настоящими нажатиями мыши и клавиш: желоб, область
  результата, строка состояния, Escape, Ctrl+Shift+F2.
- Каждая из этих проверок падает, если убрать проверяемое поведение.
