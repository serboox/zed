# Несколько запусков в одном окне: что это задело

Редактор писался в расчёте на один запуск («the run»). Теперь в одном окне
одновременно живут несколько задач, каждая в своём терминале, и отладочные
сессии. Ниже — что нашёл обход четырёх областей кода (терминалы, задачи и
конфигурации, отладчик и метрики, оболочка окна). Каждый пункт прочитан в коде;
где вывод не проверен запуском, это помечено.

Статус: **исправлено** — сделано и покрыто тестом; **решение** — нужно Ваше слово,
потому что меняется поведение; **не трогал** — известно, но вне этой правки.

## Исправлено

| Что | Что видел пользователь | Что теперь |
|---|---|---|
| Метрики брали только последний терминал задачи (`run_metrics_status_item.rs`) | С тремя запущенными приложениями цифры и процессы — только одного | Окно метрик: вкладка на каждый запуск, у каждого свои графики, дерево процессов, горутины. Плашка складывает CPU, память и процессы всех запусков и пишет «runs N» |
| Завершённый терминал считался запуском, терминалы в центре окна не считались | Мёртвая вкладка прятала живые запуски; опрос `/proc` шёл впустую | Запуском считается работающая задача в любом терминале окна |
| Порядок вкладок зависел от порядка терминалов | Вкладки менялись местами под курсором | Запуски держат порядок, в котором появились |
| Горутины: одна сессия Delve «на всех» | Число горутин одного приложения показывалось у другого | Сессия берётся по имени запуска; единственная сессия при единственном запуске — как раньше |
| «N running» и «Stop all» считали только строки списка конфигураций (`configurations_toolbar.rs`) | Запуски из окна задач, с гуттера, вытесненные из списка временные — не считались и не останавливались | Счёт и «Stop all» идут по терминалам и сессиям окна |
| Restart брал задачу из истории задач | История забывает задачу при правке `.zed/tasks.json`: Restart останавливал запуск и открывал выбор задачи; «Restart all» делал это N раз | Restart запускает саму конфигурацию |
| Одинаковый id у всех уведомлений «не удалось запустить» | Если несколько запусков не стартовали, видна причина только последнего | Уведомление на каждую причину |

## Решение за Вами

| # | Что | Где | Что видит пользователь | Предложение |
|---|---|---|---|---|
| 1 | Выход из редактора не смотрит на запуски | `zed.rs` (`confirm_quit`), `workspace.rs`, `terminal.rs` (Drop) | Закрытие окна молча убивает все запуски в доке; потомки в своей группе процессов могут пережить редактор и держать порты (в рантайме не проверено) | Перед выходом и закрытием окна один раз предупреждать «Запущено N приложений» и останавливать дерево процессов через `stop_for_good` |
| 2 | Закрытие вкладок / выход с ≥2 запусками в центре окна | `pane.rs`, `terminal_view.rs` | Вопрос «Сохранить изменения в следующих файлах?» с пустым списком; ровно одна вкладка закрывается без вопроса | Свой вопрос про запущенные задачи с их именами |
| 3 | Каждый новый запуск забирает фокус и переключает вкладку терминала (`reveal: always` по умолчанию) | `terminal_panel.rs` | Запуск третьего приложения прячет лог, который читаете | Не переключать вкладку и не забирать фокус, если на экране уже другой запуск |
| 4 | «Several at once» в форме конфигурации не действует | `configurations_view.rs`, `run_a_task_on` | Опция сохраняется, а Run из списка всё равно останавливает предыдущий запуск | Либо убрать опцию, либо уважать её |
| 5 | Падение фонового запуска никак не заметно | `terminal_view.rs`, `terminal.rs` | Уведомлений о завершении нет; при 5 запусках упавший — тихо | Уведомление «X завершился с кодом N» |
| 6 | Ctrl+Alt+R и Alt+T перезапускают «последнюю запущенную задачу вообще», а не ту, что показана на плашке | `tasks_ui.rs`, `task_inventory.rs` | Плашка говорит одно, клавиша делает другое; у плашки нет своих клавиш | Клавиши для Run/Stop/Restart плашки и для «stop all» |

## Не трогал

| Что | Где | Комментарий |
|---|---|---|
| Restart плашки на отладочной сессии молча ничего не делает | `configurations_toolbar.rs` | Нужен запуск в тесте с настоящей сессией DAP. Кнопку стоит отключать с подсказкой «перезапуск — из отладчика» |
| Stop и «Stop all» гасят только первую сессию с таким именем; сессия, начатая кнопкой Debug у задачи, не видна плашке | `configurations_toolbar.rs`, `the_session_of` | Сопоставлять по всем сессиям и по выведенному имени |
| `zedcli`: `running` у отладочных конфигураций всегда `false`; `stop --running` их пропускает; окно выбирается по первому совпавшему префиксу пути | `cli_requests.rs` | Добавить id/pid сессии в `DebugSessionInfo`; при двух окнах одного проекта — сообщать о неоднозначности |
| Restart конфигурации с несколькими одновременными экземплярами схлопывает их в один | `configurations_toolbar.rs`, `cli_requests.rs` | Актуально только для `use_new_terminal` и `allow_concurrent_runs` |
| Кнопка ↻ на вкладке терминала перезапускает не ту вкладку, если у нескольких одинаковое имя | `terminal_panel.rs` | Передавать в перезапуск нажатый терминал |
| Терминал для повторного использования выбирается по имени задачи | `terminal_panel.rs` | Две конфигурации с одним именем убивают запуски друг друга; сопоставлять по хешу шаблона, как `run_instances.rs` |
| `stop_for_good` сканирует `/proc` дважды на запуск в потоке интерфейса | `run_instances.rs` | «Stop all»/«Restart all» с N запусками — 2N сканирований подряд; один общий снимок |
| Опрос метрик читает файлы каждого потока каждого процесса машины раз в секунду | `process_metrics.rs` | От числа запусков не зависит (снимок общий), но дорого; читать потоки только у процессов запуска. Стоимость не измерял |
| Отладочные сессии в метриках не появляются | `run_metrics_status_item.rs` | Их вывод идёт в терминал отладчика, а не в терминал задачи |
| Одновременные сессии отладки: остановка в одной забирает панель и F10 у другой | `debugger_ui` | Поведение апстрима |
| Правка `.zed/tasks.json` стирает историю задач всего проекта | `task_inventory.rs` | Теперь Restart от неё не зависит; «Rerun» и список недавних — по-прежнему |
| SSH и WSL: pid запуска — это локальный клиент | `run_instances.rs`, метрики | Метрики и сигналы описывают клиента, а не удалённый процесс (не проверялось) |
| Восстановление окна: запуски, помещённые в центр, могут вернуться пустыми вкладками терминала | `workspace.rs`, `terminal_view.rs` | Не проверялось |
